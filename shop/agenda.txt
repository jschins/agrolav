why does admin not run on  http://expenses.apsurt.nl:9100  
but on  http://127.0.0.1:19100.

Because of how it’s bound and how you reach it:

On the droplet, admin listens on 127.0.0.1:9100 only — not on the public interface. http://expenses.apsurt.nl:9100 never hits that process.
The SSH line -L 19100:127.0.0.1:9100 means: your browser talks to your PC’s 127.0.0.1:19100, and SSH forwards that to the droplet’s localhost:9100. So the URL is local, not expenses….
Shop on :9000 works publicly because it was started with SHOP_HOST=0.0.0.0 (and that port is reachable). Admin was left private on purpose.

To use http://expenses.apsurt.nl:9100 you’d need ADMIN_HOST=0.0.0.0 and firewall/Caddy allowing 9100 — usually worse than the tunnel for an admin UI.

how do i know whether it operates on the remote database or on the local database?

It depends which admin process the browser hits — not the URL host alone.

What you open	                                    Which admin	                    Which DB
http://127.0.0.1:19100 via SSH -L 19100:…9100       droplet uv run admin            droplet /opt/agrolav/.env → remote webshop
http://127.0.0.1:9100 with local admin              your PC                         local root .env → usually Docker 127.0.0.1,1433 / webshop

The tunnel only forwards HTTP. SQL stays on the machine where admin runs.

Quick checks

+ Tunnel session open + droplet admin running → 19100 = remote DB.
+ Local terminal admin on 9100 → local DB (unless local .env points SERVER= at the droplet, which it normally must not).

On each side, without printing secrets: look for SERVER= / DATABASE=webshop in that machine’s env for the process — droplet vs C:\Coding\agrolav\.env.
