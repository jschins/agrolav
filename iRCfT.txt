i introduced in all three transactions tables, a column "modification" initialized at M = -1

furthermore, i deleted the column "cat_id_set" and renamed the column "cat_id_calculated" to "category_id"

the meaning of the possible values of modification:
M=-1: the categories have never been calculated (this is the initial situation, when banking statements have just been downloaded from the bank and uploaded into the database)
for M >=0, the categories have been calculated
M=0:  the user did not modify the transaction by hand (neither category, nor description)
M=1:  the user modified only the category
M=2:  the user modified only the description
M=3:  the user modified both

for both a manual category or description modification, the existing values are overwritten
this was previously the case only for the description
not for category: that value ended up in cat_id_set
however, now i want this to change
the category_id value is simply overwritten , but the manual change is reflected in the value of manual

consequences of M value on CSS:
M=1: category value shows bold in the table
M=2: full transaction line shows blue in the table
M=3: both


i want to introduce the concept of "incremental Recalculation of Categories for Term (iRCfT)"

1. to this end, introduced the column transaction.hit VARCHAR(64) NULL
the value registers the category-determining term, according to the priority rule set

2.1. A Personal Term beats all General Terms
2.2. && beats non-&&
2.3. a "later term" beats an "earlier term" in categorical-alphabetical ordering

the latter simply means that
+ on calculating the category, all the terms in the G- and P-tables are applied to the concatenation of the Name and Description fields one by one
+ everytime a hit is found, it overwrites the category for that hit, and the term in transaction.hit, unless the priority rules forbid it
+ the third rule then means that, if the first two rules are heeded, and a later applied term gives a hit, the earlier registered category is simply overwritten , i.e., the last value sticks

the concept of "incremental Recalculation of Categories for Term (iRCfT) means that
+ whenever a NEW TERM IS ADDED to the G or P-table, all transactions are recalculated one by one for this newly added term only;
  a transaction is not recalculated
  -  when its category was hand-set (M=1 or M=3)
  -  when the hit term has priority over the newly added term
+ whenever an OLD TERM IS DELETED from the G- or P-table, only those transactions are recalculated, which show that term in the hit column


this is meant to speed up calculations
does this make sense to you?
